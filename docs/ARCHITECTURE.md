# 架构与设计

## 工程

```text
src/OpenFenestra.Core/   布局模型、校验、路径引用、分类、磁盘存储
src/OpenFenestra.App/    WPF 界面、系统托盘、Shell 图标、文件监听、Win32 窗口定位
tests/OpenFenestra.Tests/ 无额外测试依赖的核心回归测试程序
scripts/                 构建、测试、便携版打包
```

Core 不依赖 WPF 或 Windows Forms。App 的状态修改统一在 UI Dispatcher 中完成。

## 数据模型

`Layout → FenceGroup[] → FenceTab[]`

- `Layout`：版本、桌面层和自动归类开关、分组列表。
- `FenceGroup`：名称、颜色、不透明度、窗口坐标和尺寸、折叠/锁定/可见状态、当前标签页。
- `FenceTab`：名称、可选文件夹路径、普通引用列表。配置文件夹路径后采用只读实时内容，原有引用仍保留。

路径只接受文件系统绝对路径。导入会校验结构、数量与标识，限制文件为 8 MB、100 个分组、每组 30 页、每页 10,000 项，并规范化几何范围。导入不会自动启动任何文件。

## 文件行为

引用操作只修改 JSON 中的路径列表，不使用移动、删除或复制文件 API。映射页不执行文件写入。图标通过 `SHGetFileInfo` 获取，释放所有原生 HICON；图片在后台加载，冻结后交回 UI，缓存限制数量。

文件夹监听只监测当前映射目录的第一层，事件经 Dispatcher 防抖后更新。监听器随标签页切换和面板关闭释放。自动归类监听用户桌面与公共桌面；旧引用保持，以免因外部文件移动丢失用户的组织关系。

## 存储与恢复

使用同目录临时文件写入并 Flush，然后通过 File.Replace 原子替换已有布局，保留 `.bak`。启动遇到损坏主文件时尝试备份，并另外保留损坏文件；主文件与备份均不可用时停止启动，避免静默覆盖。

布局修改 500 ms 防抖保存，正常退出时立即保存。快照是完整布局副本，恢复和移除分组/标签页前创建快照。未来格式版本拒绝导入，不能假定旧版本了解新字段的含义。

## 窗口集成

普通模式为无边框独立 WPF 窗口，不置顶、不注入 Explorer。实验桌面模式寻找 Explorer 桌面宿主，用 SetWindowPos 仅调整本程序窗口。它不能保证所有 Windows 构建上的“显示桌面”行为，故默认关闭。

Ctrl+Alt+Space 通过 RegisterHotKey 注册。冲突时保留托盘速览入口，并在管理窗口提示。每个数据目录用命名互斥体限制单实例。第二个实例提示用户从托盘打开管理窗口。

## 有意保留的边界

- 桌面原图标不隐藏、不重排。
- 不添加开机启动项，不修改注册表或系统设置。
- 不提供插件、脚本执行、遥测、在线账户或更新服务。
- 文件名/路径、布局和日志只保存在用户选择的数据目录。导出文件含路径，交由用户决定是否分享。
