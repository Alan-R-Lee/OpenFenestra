# OpenFenestra 项目迭代

让新对话从当前代码和已验证事实继续工作，而非重新设计产品。默认用中文与维护者交流。

## 接手

1. 在当前检出目录定位 `OpenFenestra.sln` 与 `git rev-parse --show-toplevel`；核对远程是维护者指定的 OpenFenestra 仓库或其 fork。技能安装目录不一定是项目根目录，不依赖固定盘符、用户名或原对话。
2. 读取根目录 `AGENTS.md`、`docs/DEVELOPMENT_STATE.md`，检查 `git status --short`、当前分支及最近提交。状态记录是注明日期的快照；与实际代码、远程不一致时，以重新核查结果为准。
3. 按任务阅读根目录下的文档，而非每次全量加载：
   - UI / 图标 / 拖放 / 原生桥接：`docs/ARCHITECTURE.md`；改协议再读 `docs/NATIVE_PROTOCOL.md`。
   - 构建、工具链、日常安装：`docs/BUILDING.md`。
   - 验证范围和真实桌面操作：`docs/TESTING.md`。
   - 打包、版本与 GitHub Release：`docs/RELEASING.md`。
   - 性能工作：`docs/CODE_REVIEW.md`。
   - 探索实现、排查既有方案为何失效：读 [开发经验](references/lessons.md)，再读 `docs/REFERENCES.md`。

## 保持产品与数据约定

- 保留 Explorer 原生 Windows 桌面。只创建分栏、管理窗口与托盘；不恢复全屏图标替代层，不隐藏整个桌面列表，也不把收纳项目停到屏外。
- 原生整合只抑制已收纳项目的绘制及相关输入，失败时恢复原生行为。它是独立实现，不能宣称与 Fences 内部机制或兼容性相同。
- 收纳、归类和普通排序操作不移动、删除或改写原文件。按稳定路径 / Shell 身份管理排他归属，不能按显示名称猜测项目。
- 保留现有标签页、高清图标、双击折叠 / 单击展开、折叠透明度、登录默认折叠、分组顺序和设置页体验；按用户新要求迭代，不把历史偏好固定成禁止修改。
- 支持范围是 Windows 11 x64。原生 hook、私有 OLE 属性及虚拟桌面 COM 有兼容边界，未知 Windows 版本不能默认成功。
- 发布与文档保留 MIT、第三方完整许可证和 README 中维护者指定的 AI 开发声明。不从专有 Fences 安装中提取代码或资产进入发行包。

## 实施和验证

- Core 处理布局、归属与存储；WPF App 处理窗口、Shell 和启动；C++ 桥接处理 Explorer 绘制、输入和 OLE。先定位职责，再改最小必要范围。
- 开发副本使用独立 `.qa/<本次任务>/...` 数据目录。日常实例启用原生整合时，开发副本不要同时接管 Explorer。数据目录与单实例边界见经验文件。
- UI 小改用相关构建、冒烟或交互检查；业务逻辑用 Core / Shell 测试；原生改动追加隔离原生测试。完整发布运行发布指南中的全部检查。测试数量是历史基线，报告实际结果，不为纯文案或颜色添加镜像测试。
- 原生隔离测试不接入 Explorer。真实桌面测试 `scripts/test-desktop.ps1` 会暂时改变实际显示归属，须先读测试说明、关闭其他原生整合实例，并在当前任务授权范围内操作。不要为了验证擅自重启 Explorer、结束日常实例或关闭电脑。
- 修改 Shell 热路径优先减少重复枚举和 COM 调用，复用现有批处理 / HashSet / 图标队列；保留线程亲和、资源释放、取消和故障恢复语义。性能结论需要相同场景的测量支持。
- 更新日常安装前核实实际 EXE / 数据目录并备份布局；用应用正常退出路径关闭匹配实例。安装脚本拒绝覆盖运行中的副本是保护措施，不绕过。构建新版本不等于用户正在运行新版本。

## Git、发布与交接

- 分支和同步目标从当前检出与任务确认；新分支通常使用 `codex/`。在维护者授权同步的任务内提交、推送；技能本身不授予写远程、改可见性、重写历史或发布新版本的权限。
- 使用 GitHub 隐私提交邮箱。2026-11-03 已清理历史个人邮箱，旧克隆不要直接合并 / 强推回远程。正常迭代不再重写已发布历史。
- 版本以 csproj 为准，同时检查界面、README、发行说明及安装器输出；常规维护不自动递增版本或移动现有标签。
- `v*` 标签会触发正式发布工作流；创建标签前读取 `.github/workflows/build.yml` 并完成验证。现有发布任务使用 `gh release create`，重推已发布标签会撞到已有 Release，不能把它当普通更新命令。
- 二进制经 Releases / Actions 分发，不提交到 Git 文件树。保留小体积 Light、包含 runtime 的 Offline、便携 ZIP 及 SHA-256；不为 WPF 启用未经支持的 trimming / AOT。
- 每次有实际进展时，在同一变更中更新 `docs/DEVELOPMENT_STATE.md`：日期、完成项、实际验证及产物位置、未解决问题 / 下一步、是否更新本机、是否同步远程 / 发布。通用设计和验证文档有变化时同步修改；不堆积逐工具操作日志，不写个人路径、布局、凭据或未经验证的完成声明。
- 结束前说明实际改动、验证、当前运行 / 发布状态与剩余事项。Skill 负责可复用方法，状态文档负责最新事实；不要把整段聊天历史复制成永久规则。
