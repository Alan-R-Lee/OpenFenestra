# 已形成的开发经验

按需读取。这里记录决策原因，具体实现和边界以当前源码、架构及测试文档为准。

## 路线演进

- 最初探索过全屏桌面图标替代窗口，维护者明确要求继续使用原生 Windows 桌面，因此该方案已移除。
- 屏外停放收纳图标会受 Explorer 排列与恢复影响，也未成为当前消重方案。现在是原创 C++ 组件在 Explorer 桌面线程中按项目身份抑制绘制 / 输入。
- 直接操作磁盘文件不能等同于原生桌面管理；回收站等虚拟项目要从真实桌面视图枚举。导航命名空间中的条目不一定实际出现在桌面。
- 常见公开样例仅提供桌面宿主或私有虚拟桌面调用，不能据此证明实现了 Fences。参考资料、上游许可证与引入代码的范围必须分别核实。

## Shell 桥接的关键约束

- 桌面链为 `Progman/WorkerW → SHELLDLL_DefView → SysListView32`。桥接通过指定桌面线程的短暂 hook 初始化，随后移除启动 hook。
- 收纳快照按完整身份匹配。列表重排先清旧索引；绘制回调不逐项查询 Shell COM。仅隐藏绘制还不够，选择、焦点、命中和 OLE 路径必须配套处理。
- `WM_COPYDATA` 是同步跨进程消息：接收时只校验 / 发布元数据，之后异步重建身份表。同步输入回调中 Shell COM 调出曾导致 `RPC_E_CANTCALLOUT_ININPUTSYNCCALL`。
- 私有 `OleDropTargetInterface` 存在兼容风险。尊重其他组件替换的目标，不无条件覆盖；保护能力失败时先停止抑制。
- DLL 在 Explorer 固定驻留；关闭整合不保证 DLL 立即卸载。安装器不能为解除锁而擅自重启 Explorer。缓存用内容哈希目录，并检查已加载模块身份，避免旧 DLL 被误认为新版本。
- 打包宿主下逻辑可读路径不一定能被 Explorer 装入；保留基于句柄解析物理文件路径的处理。
- 心跳与控制器 PID / HWND / token / 原进程句柄共同绑定。超时恢复依赖 Explorer 消息线程可运行，不描述为任何卡死下的硬实时保证。

## 文件、窗口和启动

- 分栏返回桌面使用 private-only 拖放数据，避免 Explorer 按普通 FileDrop 移动真实源文件。桌面外项目返回时创建不覆盖的快捷方式，不宣称批量创建是原子事务。
- 布局使用 v2 模型和原子保存 / 备份；遇未来版本显式拒绝，不拿旧备份覆盖它。文件夹映射是只读实时视图，不参与普通页排他归属。
- `--data-dir` 优先，其次 `--portable` / EXE 旁 `portable.mode`，再是当前用户 LocalApplicationData。仅换 EXE 路径并不能保证数据隔离；`--exit` 必须指向匹配的数据目录实例。先看 `App.xaml.cs`，不要猜默认路径。
- 登录模式 `--autostart` 在创建窗口前折叠分栏，保留展开高度，避免展开内容闪现。优先显示保存的窗口，再连接 Shell；任务手动触发成功不代表真实重启启动耗时已经验收。
- Shell 图标提取需要后台 STA，返回冻结后的图像，释放 COM / HICON / HBITMAP。只响应顶层 DPI 变化；保留取消、合并和缓存机制，避免每个子元素重复刷新。
- 批量收纳 / 整理已有 HashSet 和分类队列优化，不恢复嵌套全量扫描；折叠组不急于加载全部图标。历史基准是合成负载，不能直接当作实际开机提升。

## 工具与发布排错

- 标准工具链见 `docs/BUILDING.md`；现有本机可能有 `.tools/dotnet/dotnet.exe`、`.tools/inno-setup/ISCC.exe`，先检查是否存在，不把本地缓存当项目依赖。启动直接生成的 apphost 时，必要时将 `DOTNET_ROOT` 指向实际 SDK / runtime。
- 本机曾用 MinGW，CI 用 MSVC，产物体积和哈希不同属正常；不要用本机哈希校验 CI 资产。安装包必须保留对应工具链 runtime 许可证。
- Light 缺少 .NET 10 x64 Desktop Runtime 时提供 Microsoft 官方下载指引，不自动提权下载安装运行时；Offline 自带 runtime。正式 EXE 当前未签名。
- `scripts/test-installer.ps1` 拒绝在已注册真实安装的用户环境执行，避免卸载日常安装；应使用干净测试用户 / 环境，不删除注册信息来绕过保护。
- GitHub 连接器曾对私有仓库返回 404，不能单凭这个判断维护者无权限。可核实已配置的 git 访问或受支持的其他通道；不要输出凭据，也不要把认证头转发到 Release 下载重定向域名。
- `.qa` 可能有一次性修改脚本，不是稳定接口；历史中某些检查脚本也会创建 PR，不要按文件名推断为只读。读取脚本后决定是否使用。
- 用户曾允许调试操控电脑，这不等于每次新任务都要求结束进程、重启、关机或消耗账户额度。按当前任务判断必要操作；不要把旧对话的一次性授权固化成自动动作。
